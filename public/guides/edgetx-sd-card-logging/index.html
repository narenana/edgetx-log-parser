How to enable SD card logging on EdgeTX (and OpenTX)

To enable SD-card logging on EdgeTX or OpenTX, add a Special Function to your model, set its action to SD Logs, bind it to a switch, and give it a log rate (1.0s is a good default). Flip that switch and your radio writes a timestamped CSV to the /LOGS folder on its SD card. Every telemetry sensor your model receives becomes a column in that file.

One thing to know up front: the log only contains what your telemetry actually sends. If you want GPS position (and a 3D map afterward), your model needs a GPS sensor reporting to the radio. No GPS sensor means no coordinates in the CSV.

Step-by-step: add the SD Logs Special Function

This lives per-model, so set it on the model you actually fly. On the radio:

  1. Long-press MENU (or the model icon) to open the model setup pages, then page across to SPECIAL FUNCTIONS (older OpenTX calls it Special Functions too).
  2. Pick an empty SF slot. For the trigger, choose a switch — a spare 2- or 3-position toggle is ideal (e.g. SA). You can also use ON if you want it always logging while the model is on.
  3. Set the action to SD Logs.
  4. Set the log rate (the value next to the action). This is the sample interval in seconds — 1.0 is a sensible default; 0.5 or 0.2 gives finer resolution at the cost of larger files.
  5. Make sure the function is enabled (the checkbox/tick at the end of the row).

When the switch is active, the radio logs. When it's off, it stops and closes the file.

What actually ends up in the CSV

EdgeTX logs whatever telemetry sensors are currently discovered for that model. So the columns you get depend entirely on your hardware and link:

  • Always present: a date and time column, plus timestamp.
  • Link stats (RSSI/LQ, RxBt, etc.) if you run a telemetry-capable link like ELRS or Crossfire.
  • Flight-controller data (attitude, altitude, current, cell voltages) if your FC passes telemetry back over MSP/CRSF.
  • GPS latitude/longitude, altitude, speed and heading only if a GPS sensor is reporting — either a standalone GPS telemetry sensor or an FC feeding GPS up the link.

If a sensor isn't in your telemetry screen, it won't be in the log. A quick tip: before flying, go to the telemetry page and Discover new sensors so everything is registered first. If GPS never shows up there, the CSV won't have position and the 3D globe in the viewer will be unavailable — but every other chart still works.

Copy the CSV off the SD card

Logs are written to the /LOGS folder at the root of the radio's SD card, named per model with the date, for example MyWing-2026-07-15.csv. To get the file:

  • USB mass storage: plug the radio into your computer with a USB-C/USB cable and, on the radio, choose the USB Storage (SD) option when prompted. The SD card mounts as a drive — open /LOGS and copy the CSV.
  • Card reader: or just pop the microSD out and read it directly.

Each flight session appends to that model's daily file, so one CSV can hold several flights. That's normal — the viewer's timeline lets you scrub between them.

After the flight: open your CSV

Once you have the CSV, open it in the RC Log Viewer. Parsing happens entirely in your browser, so the file — including the GPS coordinates of your flying field — never leaves your machine. You get synced charts and a scrubbable timeline; if the log has GPS columns, you also get a 3D flight replay on a satellite globe.

Frequently asked questions

Why is my EdgeTX log empty or missing columns?
A CSV only records the telemetry sensors your radio has discovered. If a value (voltage, GPS, altitude) isn't on your telemetry screen, it won't be logged. Go to the telemetry page and run Discover new sensors before flying, and make sure your link actually sends that data back.
Do I need GPS for SD-card logging to work?
No. Logging works with whatever telemetry you have. GPS only matters if you want map position and 3D replay afterward — that requires a GPS sensor reporting to the radio. Without it you still get every non-position chart (attitude, altitude, battery, signal, RC inputs).
What log rate should I use?
1.0 second is a solid default and keeps files small. Drop to 0.5s or 0.2s if you want finer detail for tuning or crash analysis; the tradeoff is larger CSV files. The rate is the number next to the SD Logs action in the Special Function.
Where does EdgeTX save the log files?
In the /LOGS folder at the root of the radio's SD card. Files are named per model with the date, and multiple flights on the same day append to the same file. Copy them off via USB storage mode or a microSD card reader.
Does this work on OpenTX too?
Yes. The workflow is the same on OpenTX: add a Special Function with the SD Logs action, bind it to a switch, set a rate. Menu labels differ slightly between versions but the concept is identical, and the CSV format opens in the same viewer.
Can I log automatically without flipping a switch?
Yes — set the Special Function trigger to ON instead of a switch, and it logs whenever the model is powered. Binding it to a switch just gives you manual control over when logging starts and stops, which keeps files tidy.
