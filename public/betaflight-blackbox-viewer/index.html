Betaflight blackbox viewer that runs in your browser

RC Log Viewer is a browser-based Betaflight blackbox viewer: drop a .bbl, .bfl, or .txt log onto the tool and it decodes it in your browser, then draws synced charts for RC inputs, attitude (roll/pitch/yaw), battery voltage, altitude, and radio signal. Nothing installs and nothing uploads — the log is parsed locally with WebAssembly.

For most racing and freestyle quads the log has no GPS, so the 3D globe stays off. That's fine: crash and tune review lives in the telemetry bar and the charts, and those work on every Betaflight log regardless of GPS.

What you get from a Betaflight log (GPS or not)

Betaflight blackbox is mostly about what the flight controller was doing, not where it was. RC Log Viewer reads the record and gives you:

  • RC inputs — your stick commands over time, so you can line up a twitch or a crash with what you actually asked the quad to do.
  • Attitude — roll, pitch, and yaw, so you can see oscillation, bounce-back, or a flip.
  • Battery — pack voltage and per-cell voltage in the live telemetry bar, so you can spot a sag that browned out the FC mid-punch.
  • Altitude & vertical speed and signal — where the log includes them.

Scrub the timeline and every chart plus the telemetry bar move together, so you read one moment across all channels at once. For a walkthrough of what each trace means, see how to read a blackbox log.

Why most Betaflight logs skip the 3D globe

The 3D satellite replay needs real GPS coordinates in the log. Racing and freestyle quads usually fly without a GPS module, so a Betaflight blackbox from a typical quad has no position data — the globe is simply unavailable for that log. That's expected, not a failure of the file.

Everything else still works. The telemetry bar and all synced charts read fine from a GPS-less log, which is exactly what you want for tuning and crash review. If your quad does carry a GPS (a long-range or cruiser build), those coordinates get picked up and the globe becomes available. GPS-equipped and fixed-wing builds on iNAV are more likely to have full position — that's covered on the iNAV blackbox viewer page.

Opening a .bbl, .bfl, or .txt file

Betaflight writes blackbox in a few shapes depending on where it was logged and how you pulled it off:

  • .bbl / .bfl — the raw binary blackbox, either from onboard dataflash or an SD card.
  • .txt — a log some setups export; RC Log Viewer reads these too.

Steps: open the viewer, then drag the file in (or click to browse). One thing to know about the format: a single .bbl can contain more than one arm/disarm session concatenated into the same file, so a big file is often several short flights back to back. If you're not sure which format you have or how to get the file off the quad, see how to open a .bbl file.

How this differs from Betaflight Blackbox Explorer

The official Betaflight Blackbox Explorer is a desktop app you download and install. RC Log Viewer covers the common review workflow without any of that:

  • Nothing to install — it runs in the browser. There's also an installable PWA that works offline, plus free desktop builds for Windows, macOS, and Linux on GitHub releases if you prefer an app icon.
  • Nothing uploaded — parsing happens on your machine with WebAssembly. When a GPS is fitted, your blackbox embeds the coordinates of your flying field; because nothing leaves your machine, that stays private.
  • Core review data — synced RC input, attitude, battery, altitude, and signal charts with timeline scrubbing.

It's a focused review tool, not a full PID-tuning suite, so reach for it when you want to quickly read a flight or a crash rather than run spectral analysis.

Reviewing a crash

For a suspected crash or desync, work backwards from the end of the log. Scrub to the last moments and read the channels together: did battery voltage sag hard right before things went wrong? Did RC input show a command the quad didn't follow (a sign of failsafe or a motor giving up)? Did attitude diverge from your stick input? Because the charts and telemetry bar are synced to one timeline, you can pin the exact instant and see every channel at once. There's a full method on analyzing a drone crash log.

Frequently asked questions

Does the Betaflight blackbox viewer need GPS in the log?
No. GPS is only needed for the optional 3D globe replay. Most racing and freestyle Betaflight logs have no GPS, and the telemetry bar plus every synced chart (RC inputs, attitude, battery, altitude, signal) still work fully.
What file formats does it accept?
Betaflight blackbox as .bbl, .bfl, or .txt. iNAV blackbox and EdgeTX/OpenTX CSV telemetry logs are also supported by the same viewer.
Which Betaflight versions are supported?
Betaflight blackbox up to 4.5.x. Logs are decoded in your browser with WebAssembly.
Is my log uploaded anywhere?
No. Parsing is 100% client-side, so the log never leaves your machine. That matters because your blackbox can embed the GPS coordinates of your flying field when a GPS module is fitted.
How is this different from Betaflight Blackbox Explorer?
Blackbox Explorer is a desktop app you install. RC Log Viewer runs in the browser (with an optional offline PWA and free desktop builds), uploads nothing, and gives you the core review charts for crash and tune analysis.
My .bbl seems to hold several flights — can it read that?
Yes. A single .bbl often concatenates multiple arm/disarm sessions into one file. The viewer decodes the file so you can review the logged flight data and scrub the timeline through it.
