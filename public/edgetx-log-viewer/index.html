EdgeTX log viewer for radio telemetry CSV files

RC Log Viewer opens EdgeTX and OpenTX telemetry logs — the CSV files your radio writes to its SD card — directly in the browser, with no upload and no account. Drop a .csv from the radio's /LOGS folder onto the viewer and it charts the telemetry the radio recorded: attitude, altitude and vertical speed, speed and heading, battery per-cell voltage and signal, with your stick inputs in the live telemetry bar. ELRS link stats (1RSS, 2RSS and RQly) go on the signal chart.

If the log includes a GPS telemetry sensor, you also get a 3D flight replay on a satellite globe. If it doesn't — common on a pure quad with no GPS — the globe is unavailable but every synced chart and the live telemetry bar still work.

How EdgeTX and OpenTX write CSV logs to the SD card

When telemetry logging is enabled, EdgeTX and OpenTX write a plain CSV file to the /LOGS folder on the radio's SD card. Each row is a timestamped snapshot, and the columns are the telemetry sensors your model has discovered — so the exact columns differ from model to model. Typical columns include a date/time, RxBt or VFAS for pack voltage, cell data, RSSI/RQly/TQly for link quality, plus whatever your flight controller or vario feeds back.

  • File names look like ModelName-YYYY-MM-DD.csv, one file per model per day, with sessions appended.
  • The header row names every sensor; the viewer reads those names to decide which charts to build.
  • Logging can be started by a switch or logical function, so a single file can hold several flights — scrub the timeline to move between them.

Copy the file off the card over USB mass storage or with a card reader, then drop it on the viewer — there's nothing to configure and no import step.

When you get the 3D globe (GPS) and when you don't

The 3D replay needs latitude and longitude in the log. In EdgeTX/OpenTX, that position comes from a GPS telemetry sensor — most often a flight controller passing GPS over CRSF/MSP, or a standalone GPS module on the model. If a GPS sensor (with its coordinate pair) is present in the CSV columns, the viewer places your flight on a satellite globe with chase, tail, orbit, and top-down cameras.

  • Fixed-wing and GPS-equipped setups: usually have a GPS sensor, so you get the full 3D flight replay.
  • Pure quad telemetry with no GPS: the globe is unavailable, but the attitude, altitude, speed, battery and signal charts all still render from the other sensors, and the stick inputs still show in the telemetry bar.

You can preview the globe experience with a sample: fixed-wing demo.

What the viewer shows from a radio log

Everything is driven by the sensors present in your CSV, synced to one scrubbable timeline:

  • Live telemetry bar — battery per-cell voltage, altitude, speed, heading, attitude, and stick inputs at the current playhead.
  • Synced charts — attitude; altitude and vertical speed; speed and heading; battery; signal (RSSI and link quality).
  • Event jumps — skip between takeoff, RTH, and landing points, plus your own bookmarks.
  • 3D replay — on the satellite globe when GPS is present, with four camera modes.

If a chart looks empty, it usually means the radio never logged that sensor — for example, no vario means no independent vertical-speed source, and no current sensor means no battery-current trace.

Private by design, and works offline

Parsing happens entirely in your browser using WebAssembly. Your CSV is never uploaded to a server, and there's no account to create. That matters for radio logs specifically: a GPS-tagged CSV embeds the coordinates of your flying field, and because the file is read locally, those coordinates never leave your machine.

The viewer is a free, open-source (GPL-3.0) installable PWA that runs offline once loaded, and there are free desktop builds for Windows, macOS, and Linux on the project's GitHub releases if you prefer a standalone app.

Frequently asked questions

Does the EdgeTX log viewer work with OpenTX logs too?
Yes. OpenTX and EdgeTX write telemetry CSV in the same way, and the viewer reads both. If your radio runs either firmware, drop the CSV from its /LOGS folder and it opens.
Where do I find the CSV log on my radio?
On the SD card in the /LOGS folder. Files are named per model and date, like ModelName-2026-07-15.csv. Copy them off via USB mass storage or a card reader, then open them in the viewer.
Why is the 3D globe missing for my log?
The globe needs GPS coordinates, which come from a GPS telemetry sensor. If your model has no GPS (common on racing/freestyle quads), the log has no position data, so the globe is unavailable — but all the telemetry charts still render.
Are my logs or my flying-field location uploaded anywhere?
No. All parsing is done locally in your browser with WebAssembly. The CSV — including any GPS coordinates of your field — never leaves your computer.
Which EdgeTX and OpenTX versions are supported?
The viewer reads the standard EdgeTX and OpenTX telemetry CSV format written to the SD card, so it isn't tied to a specific firmware version. It reads whichever sensor columns your radio recorded.
Can I view blackbox logs from a flight controller here too?
Yes, but those are a different format. For Betaflight or iNAV blackbox files see the Betaflight blackbox viewer and iNAV log viewer pages.
